## 1. Rexine measurement & consumption (revisit: Week 5/6)

- `consumption_rates` table (meters-per-mat, keyed by size_class:
  small/medium/large)
- Estimate at batch creation ("~6m needed, roll R-001 has 50m ✓", warn if
  estimate > remaining)
- Actual decrement on cutting complete (cutter enters meters used; decrement
  `raw_materials.remaining_meters` in the same tx as the phase transition,
  CHECK constraint guards negative stock)
- Low-stock trigger → NOTIFY → dashboard alert (UI badge exists now;
  push notification later)

**BLOCKER:** factory has no measurement method yet. Ask owner/cutter:
"When cutting finishes, how do you know how much material got used —
measure, eyeball, or not tracked?" Answer shapes the whole feature
(precise entry vs coarse roll in/out tracking).

**INTERIM:** manual "correct remaining meters" in the Stock page is the
stopgap (built, Week 5).

## 3. Worker auth hardening (pre-production, BEFORE factory rollout)

- **30-day worker tokens can't be revoked mid-window.** Deactivating a
  worker doesn't kill their live token. Fix: check `workers.is_active` on
  every worker request (cheap query or cached), OR move to short TTL +
  refresh flow.
- Repurpose `badge_token` → proper `enrollment_code`: one-time use,
  expiring (24h), regenerable from admin. Currently it's permanent and
  reusable — fine for dev, not for production.
- `pin_hash` becomes optional backup re-auth (e.g., confirm PIN before
  sensitive actions) — or drop if unused.
- Rate-limit `/worker/login` (brute-force guard on 4-digit PINs).
- **Admin resets worker PIN** from admin web (PATCH /workers/:id/pin +
  button). Currently requires direct DB hash surgery — awkward even in dev.

## 5. Phase-flow additions (as factory needs emerge)

- **Admin force-release of a claimed batch** (worker went home mid-batch,
  phone died). Currently a claim can only be completed by its owner.
- **`phase_logs.method` ('manual'|'machine')** — compare machine vs manual
  cutting throughput. 5-minute change; add when owner asks "how much
  faster is the machine?"
- **Stitching sub-tasks via `car_models.piece_groups`** (spec Rule #19):
  split one batch's stitching between N workers (left-side/right-side).
  Field exists and is seeded; sub-task machinery NOT built. CONFIRM with
  owner first: does stitching actually get split, or does one stitcher do
  a whole batch? If never split → collapse to piece_groups=1 and skip the
  machinery entirely.
- **Rework flow** (spec state machine): failed QC → rework_count++,
  batch returns to an earlier phase. Schema has `rework_count`; no
  endpoints/UI yet.
- Short-count follow-up: quantity_completed < batch quantity currently
  just logs the number. Decide what should HAPPEN on shortage (alert
  admin? adjust batch quantity? create rework?).
